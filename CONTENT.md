# Как писать тему

Тема — один файл `content/<уровень>/<NN>-<id>.yaml`. Из него собирается страница: разбор с закреплённой сценой → шпаргалка → тренажёр → игра темы (если есть) → дело → словарь. Навигация повторяет этот порядок. Герои, места и сквозной сюжет — в [WORLD.md](WORLD.md). Образец — [content/a1/01-kennenlernen.yaml](content/a1/01-kennenlernen.yaml): прежде чем писать новую тему, прочитайте его целиком.

Проверка без записи файлов и без озвучки:

```sh
node scripts/build-content.mjs --check --only 02-zahlen
```

Сборка с готовыми аудио — `pnpm content`. Для новых или изменённых фраз сначала [экспортируйте манифест и сгенерируйте записи](scripts/tts/README.md). Пока записей нет, текст можно посмотреть на странице через `pnpm draft`: черновая сборка пишет JSON без новых записей и прячет у них кнопку озвучки. Такую сборку не коммитят.

## Формат рассказа

Тема — короткая история, а не параграф учебника. Есть герои, место и повод заговорить. Читатель листает текст слева, а сцена справа показывает то, о чём идёт речь: реплики, карточки слов, таблицу, схему предложения или задание экзамена.

Главы одинаковые во всех темах:

| Глава | id | Что делаем |
|---|---|---|
| Ситуация | `scene` | Один или два диалога, реплики открываются по одной |
| Слова | `words` | Группы слов, по одной группе на фрагмент |
| Грамматика | `grammar` | Таблицы и схемы предложений. Одна мысль — один фрагмент |
| Проверка | `practice` | Вопросы «а как сказать…». Ответ скрыт под кнопкой |
| На экзамене | `exam` | Задание в формате telc и разбор, как его решать |

Ориентиры по объёму: 18–26 фрагментов, 3–5 вопросов, 1–2 диалога по 6–10 реплик, 3–5 групп слов (30–50 слов всего), 2–4 таблицы, 12–16 упражнений.

## Тексты

- `read` — абзац на русском, 45–90 слов. Объясняйте, почему так, сравнивайте с русским, предупреждайте о типичных ошибках. Говорите с читателем на «вы».
- Каждый немецкий фрагмент в русском тексте берите в звёздочки: `*Ich heiße Anna*`. Он будет набран антиквой и выделен цветом. Кавычки вокруг немецкого не нужны. Звёздочки работают в `read`, `point`, `question`, `lede`, `goals`, `title` шага, `why` и в русских колонках таблиц.
- `point` — тезис для шпаргалки, до 120 символов. Обычно это правило плюс пример: `"*wir*, *sie*, *Sie* — как инфинитив"`.
- `question` — вопрос к читателю, до 90 символов. Ответ — в `read` того же фрагмента.
- Немецкий — только того уровня, который вы проходите, и только та грамматика, что уже была в предыдущих темах или вводится в этой (см. маршрут ниже). Готовые фразы вроде *Ich möchte …* можно давать раньше как выражение, не разбирая грамматику.
- Русский: кавычки «ёлочки», буква ё, тире —, числа цифрами.

## Разметка

| Где | Запись | Что получится |
|---|---|---|
| Русский текст | `*Ich bin Anna*` | Немецкий фрагмент |
| Немецкий текст | `wohn+st` | Окончание *st* подсвечено |
| Немецкий текст | `*heiße*` | Слово выделено акцентом |

`+` ставится перед окончанием внутри слова: `komm+e`, `ein+en`, `d+en`. Работает и в русском тексте внутри звёздочек: `*du wohn+st*`.

## Подводные камни YAML

- В записи `{ de: …, ru: … }` и `[a, b, c]` запятая разделяет поля. Если в тексте есть запятая, берите его в кавычки: `{ de: "Danke, gut!", ru: "Спасибо, хорошо!" }`.
- Строку, которая начинается с `*`, тоже берите в кавычки: `point: "*Hallo!* — приветствие"`.
- `: ` (двоеточие с пробелом) внутри строки без кавычек ломает разбор. Тоже кавычки.
- Длинные абзацы пишите через `>-`, внутри них кавычки не нужны.

Проверка ловит эти ошибки: неизвестное поле, лишняя ячейка таблицы, непарная звёздочка.

## Шапка темы

```yaml
id: zahlen                  # латиница, становится адресом страницы
order: 2                    # номер в маршруте уровня
title: Eins, zwei, drei …   # немецкое название
ru: Числа и алфавит         # русское название
lede: >-                    # 2–3 предложения: о чём история и чему научимся
goals: [ … ]                # 3–5 пунктов «Вы научитесь …»
grammar: [ … ]              # короткие ярлыки грамматики
exam: [sprechen-1, hoeren-3] # части экзамена из content/levels.yaml
```

## Материалы сцены

### Диалоги — `dialogues`

```yaml
dialogues:
  kurs:
    title: Der erste Kurstag      # по-немецки
    ru: Первый день на курсе
    place: Sprachschule, Leipzig   # необязательно
    people:
      A: { name: Anna, voice: Anna }
      M: { name: Marco, voice: Reed }
    lines:
      - A: Hallo! Ich bin Anna.
        ru: Привет! Я Анна.
```

Первый в `people` говорит слева, остальные справа. Логические голоса: женские `Anna`, `Sandy`, `Shelley`, `Flo`; мужские `Reed`, `Eddy`, `Rocko`, `Grandpa`. Это постоянные идентификаторы, а не названия модели; образцы находятся в `scripts/tts/voices`, текущая модель описана в `scripts/tts/README.md`.

Герои, их голоса и места — в [WORLD.md](WORLD.md): ученики Дана (`Anna`), Матео (`Reed`) и Элиф (`Flo`), немцы — сотрудники школы, начальник гавани, соседи. Новых персонажей сначала добавьте туда.

### Слова — `words`

```yaml
words:
  person:
    title: Angaben zur Person
    ru: О себе
    items:
      - { de: der Name, ru: имя, pl: Namen }       # мн. ч. без артикля
      - { de: das Obst, ru: фрукты, pl: "-" }      # нет мн. ч.
      - { de: die Eltern, ru: родители, pl: pl }   # только мн. ч.
      - { de: wohnen, ru: жить, note: ich wohne }  # не существительное — без pl
```

Слово с артиклем `der`/`die`/`das` в начале считается существительным, и `pl` у него обязателен. Цвет карточки показывает род. Озвучка произносит и множественное: «der Name, die Namen». `note` — короткая подсказка: форма, пример, особенность.

### Таблицы — `tables`

```yaml
tables:
  sein:
    title: sein
    ru: быть
    head: [Person, sein, Beispiel]
    rows:
      - [ich, bin, Ich bin Anna.]
    ruCols: [2]      # номера колонок на русском, с нуля; по умолчанию все немецкие
    note: Неправильный глагол — формы надо запомнить.
```

### Задания экзамена — `tasks`

У каждого задания `kind`, `part` (часть экзамена), обычно `title` и `situation` по-немецки — как в экзаменационном листе.

| kind | Поля | Что на сцене |
|---|---|---|
| `keywords` | `words`, `sample` | Лист с ключевыми словами (Sprechen 1) и образец ответа |
| `form` | `fields: [{label, value, given}]` | Анкета (Schreiben 1). `given: true` — поле уже заполнено |
| `card` | `theme`, `word` или `picture` (эмодзи), `sample` | Карточка Sprechen 2 (тема + слово) или 3 (картинка) |
| `sign` | `text`, `statement`, `answer: true/false` | Табличка (Lesen 3), утверждение richtig/falsch |
| `message` | `from`, `to`, `subject`, `text`, `points`, `statement`/`answer`, `sample` | Письмо или записка (Lesen 1, Schreiben 2) |
| `listen` | `text` + `voice` или `dialogue`; `question` + `options` + `answer` или `statement` + `answer` | Запись (Hören). `text` звучит одним голосом — для объявлений и автоответчика. `dialogue: id` проигрывает диалог из `dialogues` голосами героев — для разговоров Hören Teil 1; этот диалог не обязан появляться в сцене. Текст виден только после ответа |
| `ads` | `situation`, `options: [{title, text}]` × 2, `answer: 0/1` | Два объявления (Lesen 2) |

Перевод строк в `text` — `\n` или блок `|`. `answer` у вариантов — номер с нуля. `sample` — список немецких строк: образец ответа, каждая озвучивается.

## Фрагменты — `steps`

```yaml
steps:
  - id: treffen          # латиница
    chapter: scene
    title: Первая встреча
    beats:
      - read: >- …
        point: …
        set: { view: dialogue, dialogue: kurs, reveal: 1 }
```

`set` меняет сцену. Всё, что не указано, остаётся от предыдущего фрагмента. Когда меняется `view` или объект на сцене (другой диалог, другая группа слов), `reveal`, `focus` и `solved` сбрасываются: объект показан целиком, без выделения.

`focus` подсвечивает элементы акцентом, а остальные затемняет. Два правила:

- То, что открылось в этом фрагменте, никогда не затемняется: новые реплики диалога и новые строки таблицы, слов или схемы, добавленные через `reveal`. Иначе реплика выглядит так, будто до неё ещё дойдут. Диалог прокручивается к новым репликам, а не к последней.
- Если у фрагмента есть `focus`, в него должно входить всё, что цитирует текст. Проверка предупреждает: «… есть в тексте, но реплика N затемнена / не выделена — добавьте N в focus».

| view | Что указать | reveal | focus |
|---|---|---|---|
| `dialogue` | `dialogue: id` | сколько реплик открыто | номера реплик с нуля |
| `words` | `words: id` | сколько слов открыто | номера слов |
| `table` | `table: id` | сколько строк открыто | номера строк |
| `sentence` | `rows: […]` | — | номера строк схемы |
| `task` | `task: id`, `solved: true` | сколько полей анкеты или строк образца | — |
| `clock` | `time: "15:45"` | — | — |

### Схема предложения — `view: sentence`

Главная визуализация курса: четыре поля немецкого предложения — позиция 1, глагол, середина, конец. Каждая строка `rows` — четыре строки полей, пустое поле — `""`.

```yaml
set:
  view: sentence
  rows:
    - de: [Ich, steh+e, um sieben Uhr, auf.]
      ru: Я встаю в семь часов.
    - de: ["", Steh+st, du um sieben Uhr, auf?]
      ru: Ты встаёшь в семь?
```

- Знак препинания пишите прямо у последнего слова: `auf.`, `du?` — он станет отдельной плиткой.
- Слова одной строки с одинаковой основой — одна плитка. Если в следующем фрагменте та же строка (тот же номер) меняется, плитка переезжает на новое место: видно, как *in Leipzig* уходит на первую позицию, а *ich* — за глагол. Окончание после `+` может меняться: `wohn+e` → `wohn+st`.
- Заглавные буквы ставьте как в настоящем предложении.
- Поле «конец» и рамка между глаголом и концом показывают рамку предложения: отделяемая приставка, инфинитив после модального глагола, причастие в Perfekt.
- Схема особенно полезна, когда меняется порядок слов: вопрос, инверсия, отделяемые приставки, модальные глаголы, Perfekt.

### Часы — `view: clock`

`set: { view: clock, time: "07:30" }` — стрелки поворачиваются к новому времени, рядом официальное (*sieben Uhr dreißig*) и разговорное (*halb acht*) чтение со звуком. Обе формы считаются автоматически.

### Вопросы

```yaml
- question: Как спросить пожилую соседку, откуда она?
  read: >- ответ …
  point: …
  before: { … }   # необязательно: что показать, пока ответ закрыт
  set: { … }      # сцена после «Показать ответ»
```

Пока ответ закрыт, сцена показывает явно заданную `before`. Если её нет, показывается экран текущего вопроса, без предыдущей сцены и без готового ответа. Кнопка «Показать ответ» есть и в сцене, и рядом с вопросом в тексте; обе раскрывают один ответ. После нажатия сцена переходит в `set`. Поэтому `set` — это и есть ответ: подсвеченная строка таблицы, решённое задание (`solved: true`), новая строка схемы.

## Дело темы — `case`

Детективная история темы — глава сквозного дела уровня (см. [WORLD.md](WORLD.md)). Верный вывод на каждом шаге требует грамматики этой темы, а неверный ведёт по ложному следу с объяснением. Хорошая улика — та, которую «по-русски» прочитаешь неправильно: *sie kommen* — «они», а не «она», окончание падежа решает, кто кого видел, *halb acht* — это 7:30.

```yaml
case:
  title: Wo ist die «Sprotte»?     # по-немецки
  ru: Где «Шпротта»?
  intro: >- …                       # завязка, по-русски
  people:
    J: { name: Herr Jensen, voice: Grandpa, role: Hafenmeister }
  steps:
    - read: >- …                    # что происходит на этом шаге
      evidence:
        - J: Moin! Die Jolle ist weg.   # реплика свидетеля, озвучивается
          ru: Привет! Шлюпка пропала.   # перевод виден только после разгадки
        - note: |                      # записка, без озвучки
            Herr Jensen, …
          ru: …
      question: Сколько человек вышли в море?
      options: [Одна женщина, Двое или больше, Один мужчина]
      answer: 1
      right: >- …                    # что открывается после верного вывода
      wrong: [ …, null, … ]          # ложный след для каждого варианта (у верного — null) или один текст на все
  ending: >- …                       # развязка и крючок на следующую тему
```

Три-пять шагов. Перевод улик спрятан до разгадки, иначе он подсказывает ответ. Ложный след не ругает, а показывает, к какому неверному выводу привела ошибка и почему.

## Поиск ошибки — `spy`

Игра в тренажёре: на доске клуба четыре записки, в одной ошибка. Ищем ошибку, а не виновного: она ничего не говорит о происхождении или честности человека. Ключ `spy` сохранён ради совместимости контента. Вкладка появляется, когда фраз не меньше четырёх.

Фразы с ошибками собираются автоматически из схем предложений темы: глагол не на второй позиции и чужое окончание глагола. В `spy` добавьте ошибки, которые автоматика не придумает: пропущенная связка (*Ich Dana*), страна без артикля (*aus Türkei*), неверная форма неправильного глагола. Фразы `spy` не озвучиваются, новых записей не требуют.

```yaml
spy:
  - de: Ich bin Dana.
    wrong: Ich Dana.
    why: "Связку *sein* не пропускают: по-русски «я Дана», по-немецки *Ich bin Dana*."
```

Ошибка должна быть типичной для изучающих немецкий и ровно одна во фразе. Вариант `wrong` не должен оказаться верным предложением с другим смыслом: *Könntest du…* вместо *Konntest du…* для такой пары не подходит.

## Игровой эпизод — `adventure`

Заменяет прежнее поле `mission`. Примеры находятся в темах 1–2. Общая история и дизайн описаны в `GAMEPLAY.md`. В интерфейсе эпизод расположен после тренажёра и перед делом; словарь остаётся в конце. Игра видна в обычной навигации урока. Отдельные баннеры, общая доска и переходы на другие уроки внутри игры не используются. Поля `title` и `intro` обязательны для всех видов.

- `kind: crew`: `origins`, `places` — списки разных вариантов; `members` — участники с уникальными `id`, `name`, правильными `origin`, `home` и ссылкой `clue: {dialogue, lines: [индексы]}` или `clue: {caseStep, evidence}` на озвученную реплику дела. `contact` содержит `question`, `answer` (id участника), `success`, `wrong`.
- `kind: harbor`: `berths` и правильный `berth`; `directions`, `phoneClue`, `phoneHelp` — ссылки на реплики; `phone` — строка цифр учебного номера; `roomTask` — id задания `listen` с текстом, аудио и числовым ответом на варианты.
- `kind: sequence`: последовательность только из `challenges`, без специальных начальных шагов; `ending` — итог эпизода. Образец — «Гости команды» в теме 3.

Все виды поддерживают `challenges`. Каждый шаг содержит уникальный `id`, `kind`, `title`, `intro`, `success`, `wrong` и необязательный `clue` со ссылкой на готовую реплику. `order` собирает `tokens` в заданном порядке (с подписью `label`); одинаковые буквы взаимозаменяемы. `pack` выбирает несколько `options: [{id, label, icon?}]`, `answer` — точный набор id без лишних предметов. `select` использует тот же формат с единственным правильным id. `match` связывает `slots: [{id, label, icon?, answer}]` с `options`; `answer` поля — id варианта. Один вариант может подходить нескольким полям. Необязательный `anchor` подписывает семейную карточку. Id — латиница, цифры и дефис. Новые шаги добавляйте после существующих, не меняя их порядок без миграции сохранений. Выбранные элементы и успешная проверка сохраняются; переход к следующему шагу отдельной кнопкой позволяет прочитать результат.

Для заданий на чтение задавайте `mode: reading`: текст виден сразу и не считается подсказкой к аудированию. `mode: listening` (по умолчанию) скрывает текст записи до запроса. `clue: {task: brief}` переиспользует текст задания с его отправителем; для `message` с `points` показывает также ситуацию и пункты (без `sample`), для `ads` — ситуацию и оба объявления (без `answer`), для `form` — только ситуацию (без заполненных полей); если аудио у задания нет, реплика сразу доступна для чтения. Не дублируйте письмо в новом диалоге только ради озвучки.

`quantity` собирает корзину: `items: [{id, label, icon?, unit, pluralUnit?, answer, step, max}]`. Количество начинается с нуля, меняется кнопками и сохраняется отдельно для каждого товара. `answer`, `step` и `max` — целые числа, максимум и ответ кратны шагу; выход за границы запрещён. Для изменяемой единицы задайте обе формы: `unit: Flasche`, `pluralUnit: Flaschen`. Проверка сравнивает количество каждого товара, а не только общую сумму.

`clock` устанавливает время по сообщению: `answer: "10:30"`, `initial: "09:00"`, `minuteStep: 5`. Шаг минут должен делить 60, а оба времени должны быть достижимы. Часы меняются кнопками; переход через полночь допустим. Игра показывает выбранное цифровое время и стрелки, но не подставляет немецкое прочтение как готовую подсказку. Текст исходного сообщения доступен отдельно, выбранное время сохраняется.

Индексы реплик, шагов дела и улик считаются с нуля. В `origins` допустимы страны и города; совпадающие города среди `places` помогают отличать происхождение от места жительства. Озвучка берётся из существующих диалогов и задания. При перестановке реплик проверьте смысл ссылок и соответствие правильного ответа сообщению: проверки ловят отсутствующий индекс, но не смысловое несоответствие. Текстовые варианты должны быть уникальными. Новая реплика в диалоге требует обычной процедуры генерации TTS, новая ссылка на готовую — нет.

Все действия доступны кнопками на телефоне и с клавиатуры; обязательного перетаскивания нет. Для аудио всегда доступен текстовый режим. Прогресс эпизода не прибавляет экзаменационные баллы и не смешивается с решёнными упражнениями. Сохранение — в `sd-adventure-v1`, отдельно от старых заметок `sd-mission-v1-*`; старые заметки не удаляются.

## Упражнения — `exercises`

```yaml
exercises:
  - type: choice
    q: ___ heißen Sie?          # немецкая строка с пропуском или русский вопрос
    options: [Wie, Wo, Woher]
    answer: 0                   # номер правильного варианта с нуля
    why: "*Wie heißen Sie?* — «Как вас зовут?»"
  - type: gap
    q: Du ___ aus Italien.      # один или несколько пропусков ___
    answer: [kommst]            # ответ на каждый пропуск; варианты через |
    hint: kommen                # подсказка в скобках
    ru: Ты из Италии.           # необязательный перевод
  - type: order
    ru: Ты говоришь по-немецки?  # задание
    de: Sprichst du Deutsch?     # правильный порядок
    also: [ … ]                  # другие верные порядки
```

В сборке фразы регистр не сравнивается: плитки даны, их можно только переставлять. Первое слово показывается со строчной буквы, если это служебное слово (*ich*, *jetzt*, *am* …) или если оно стоит со строчной в одном из вариантов `also`, а в собранной строке первая буква становится заглавной сама.

В `also` перечисляйте все грамматически верные порядки: в немецком на первую позицию можно вынести разные части предложения, и верный ответ не должен считаться ошибкой. Слова в `also` должны совпадать со словами `de`, иначе сборка упадёт; запятые при проверке не учитываются. Перестановки, меняющие смысл (*Café A ist günstiger als Café B*), не добавляйте.

Варианты `choice` и вопросов дела перемешиваются при показе, поэтому порядок в YAML не важен. Если без контекста подходят два варианта, добавьте `ru`: он покажет нужный смысл и не влияет на озвучку.

Хорошее упражнение проверяет одно правило темы. Смешивайте типы, давайте `why` там, где ошибка вероятна. Тренажёр артиклей и карточки слов собираются из `words` автоматически.

## A2: задания с несколькими ответами и новое игровое действие

Темы находятся в `content/a2/`, id и части экзамена имеют префикс `a2-`. Пример: `a2-kontakte`, `a2-hoeren-3`. Это сохраняет отдельные адреса и прогресс A1. Крупные новые грамматические блоки вводятся по маршруту `A2-PLAN.md`; A2 использует более короткую новую словарную группу и повторяет знакомую лексику в действиях.

`kind: worksheet` содержит `part`, `title`, `format` (`notes`, `directory`, `article`, `matching`, `radio`, `pair`) и `questions`. У вопроса `prompt`, непустой список `answers` с допустимыми строками и, при выборе, `options`. Сопоставление и пять утверждений — пять отдельных вопросов. Свободный ввод сравнивается после нормализации регистра, пробелов и Unicode. Не добавляйте заведомо неверные варианты как алиасы.

Для аудирования задайте `text` с `voice`, `dialogue: <id>` для последовательного разговора разными голосами либо `recordings: [{text, voice}, ...]` по одной записи на вопрос. Сборка добавляет ссылки `audio` и `script`; вручную их не задают. В тренировочной сцене текст открывается отдельно, а независимые радиозаписи имеют отдельные кнопки текста. `solved: true` раскрывает ответы только в разборе.

Для короткого письма A2: `kind: message`, `text`, `situation`, четыре `points` и `choose: 3`. Пользователь выбирает три пункта и пишет свой вариант; черновик и выбор сохраняются в браузере. Объём около 40 слов. `sample` — пример, не единственный допустимый ответ. Для `kind: card` допустимы две `roles: [{title, text}, {title, text}]`; в самостоятельной работе они открываются как разные карточки собеседников. Продуктивные ответы автоматически не оцениваются.

Дополнительные игровые механики:

- `note`: `fields: [{label, answers: ["11:00", "elf Uhr"]}]`; самостоятельный ввод по сообщению. Нужны конкретные, достаточные алиасы.
- `negotiation`: `start` и `nodes`. Узел содержит `id`, `text`, `choices: [{label, next, feedback}]`. Конечный узел имеет `terminal: true`, `choices: []`. Из любого узла должен быть путь к завершению. Неверная реплика получает содержательную реакцию, затем возможность уточнить.
- `alternatives` у `select`/`pack`: дополнительные полные наборы id ответов; наборы нельзя произвольно смешивать. Например, основной `[a, walk]`, дополнительный `[b, museum]`.
- `variants`: полный список альтернативных описаний шага без вложенных вариантов. Вариант стабилен внутри попытки и меняется при повторе; тексты условий и ответы каждого варианта проверяются вместе.

У всех шагов остаются общие `id`, `title`, `intro`, `success`, `wrong`. Игры не становятся обязательным свободным письмом: заметка требует конкретного сведения, диалог использует осмысленные реплики.

## Входная работа, проверки и пробник

Источники `content/assessments/*.yaml` отдельно от 14 уроков. Поля корня:

```yaml
id: a2-check-example
level: a2
mode: review                 # либо mock
title: Проверка
intro: Новая самостоятельная ситуация.
sections:
  - id: reading
    title: Lesen
    # minutes: 50            # только при ограничении времени
    taskIds: [notice]
tasks:
  notice:
    kind: worksheet
    part: a2-lesen-2
    format: article
    title: Eine Nachricht
    text: Der Kurs beginnt am Montag.
    questions:
      - prompt: Der Kurs beginnt am Dienstag.
        options: [richtig, falsch]
        answers: [falsch]
review:
  - level: a2
    topic: a2-neustart
    label: Повторить сообщение
    taskIds: [notice]        # ссылка показывается при ошибке в этой задаче
```

Также разрешены `dialogues`, как в теме. Каждая задача должна войти ровно в один раздел. Сборка создаёт `src/generated/assessments/<id>.json` и каталог ссылок. Адрес `#/a2/<id>`. Аудио этих источников входит в общий манифест и защищено от удаления полной сборкой. Не копируйте задания или аудио официального теста; используйте только его форматы для авторского материала.

`review` не имеет обязательного таймера и лимита аудио, но скрывает ответы до завершения. `mock` сохраняет срок, ответы и количество прослушиваний в `sd-assessment-v1:<id>`. В A2 радио — один раз, телефон/разговор — два; в B1 части Hören 1/2/3 — соответственно 1/2/2; остановленная пользователем запись считается использованной, неудачный запуск звука возвращается. Автоистечение времени завершает раздел и при перезагрузке не даёт новые минуты. До окончания всей попытки нет транскриптов, примеров и правильных ответов. После завершения доступны разбор и свободное переслушивание; новая попытка сбрасывает только эту контрольную работу.


## Реализованный уровень B1

Реализованы 20 уроков, входная работа, пять проверок и пробник. Пример первого урока: `content/b1/01-neustart.yaml`, маршрут `B1-PLAN.md`, результаты проверки `B1-PROGRESS.md`. Используйте префикс `b1-` у уроков и частей экзамена; глобальный id должен оставаться уникальным.

`uniqueOptions: true` у worksheet отключает в других полях уже выбранный вариант. Это нужно для Lesen 1 с пятью текстами и десятью заголовками; правильные ответы должны быть разными, у каждого вопроса ровно один ответ из options. В обычной сцене это тренировочное задание с проверкой и повтором; ограничения времени самостоятельной работы вводятся отдельно. `roles` у карточки теперь отображаются и в сцене урока, а не только в контрольной работе.

B1 Hören 1 отличается от A2: в самостоятельной попытке пять коротких текстов слушают один раз, а Hören 2 и 3 — дважды. Учебная сцена сохраняет свободное переслушивание и отдельное раскрытие текста; такой режим не выдаётся за независимое аудирование.


### Связный текст с пропусками и письмо B1

`kind: worksheet`, `format: cloze`: в `text` вставляйте маркеры `[[1]]`, `[[2]]` и далее точно по числу вопросов. Каждый маркер встречается один раз в порядке следования. У каждого вопроса нужны `options` и единственный правильный `answers`. Выбор отображается внутри предложения, чтобы контекст оставался видимым. Для Sprachbausteine 2 у всех десяти вопросов общий банк из пятнадцати слов и `uniqueOptions: true`; правильные ответы не повторяются. Учебный режим даёт проверку и повтор, контроль сохраняет ответы и откладывает разбор до завершения попытки.

Письмо B1: `kind: message`, `part: b1-schreiben-1`, четыре обязательных `points`, **без choose**. Черновик сохраняется в сцене и в самостоятельной работе. В выбранном образце Zertifikat Deutsch нет фиксированного минимального числа слов; учебный ориентир объёма нужно явно называть ориентиром. Образец не подменяет самостоятельное письмо. В разборе продуктивный ответ проверяется по выполнению задачи, связности/оформлению и формальной правильности; автоматической оценки нет.

Для B1 Hören 2 используйте отдельный диалог и `dialogue: id` у worksheet, если собеседников несколько. Не озвучивайте подписи говорящих одним голосом как часть разговора. Дополнительный диалог должен содержать переводы реплик.

В пробнике B1 блоки имеют 90/30/30 минут, затем 20 минут подготовки и 15 минут парной практики. Закрытые части дают до 180 взвешенных баллов: Lesen 1/2 по 5 за ответ, Lesen 3 по 2,5; Sprachbausteine по 1,5; Hören 1/3 по 5, Hören 2 по 2,5. Письмо до 45 и речь до 75 оцениваются человеком. Без них нельзя вычислять итог сдачи. Источник: официальный Übungstest 1, 14-е издание 2021, печатные с. 39–40; ссылка в B1-PLAN.md.

В Lesen 3 задавайте `uniqueOptions: true`, `reusableOptions: [x]`: объявления одноразовые, но «ничего не подходит» может встречаться несколько раз. Для заголовков и банка Sprachbausteine исключение не нужно.
