# Немецкая озвучка

Все 980 записей текущего A1 сгенерированы **Qwen/Qwen3-TTS-12Hz-1.7B-Base**, checkpoint `fd4b254389122332181a7c3db7f27e918eec64e3`. Выход модели — 24 кГц, mono; веб-файлы — AAC/M4A, 96 кбит/с. Чёткие постоянные голоса предназначены для учебных слов, реплик и объявлений.

`Anna`, `Reed`, `Eddy`, `Sandy`, `Shelley`, `Rocko`, `Grandpa`, `Flo` — логические имена из YAML. Их синтетические немецкие образцы лежат в `voices/`. Они созданы Qwen3-TTS-12Hz-1.7B-VoiceDesign; точный текст, описания и источник сохранены в `voices/profiles.json`, ревизия и контрольные суммы — в `config.json`. Образцы не являются записями реальных людей.

`config.json` входит в хэш имени каждой записи. При смене модели, голоса или настроек меняется URL, поэтому браузер не использует аудио предыдущей версии.

## Обычная сборка

```sh
pnpm check
pnpm content
pnpm build
```

Эти команды не запускают TTS и не требуют GPU. Если для новой фразы нет файла, сборка остановится; системный синтезатор macOS больше не используется.

## Генерация новых записей на CUDA

Нужны Python 3.12, NVIDIA GPU и зависимости из `requirements.txt`. Проверенный runtime: PyTorch/torchaudio 2.8.0 с CUDA 12.8, Transformers 4.57.3, qwen-tts 0.1.1. Создавайте отдельное окружение; системные пакеты менять не требуется.

```sh
python3 -m venv .venv
.venv/bin/pip install torch==2.8.0 torchaudio==2.8.0 --index-url https://download.pytorch.org/whl/cu128
.venv/bin/pip install -r scripts/tts/requirements.txt
```

Числа, короткие слова и фрагменты передаются на немецком языке. Если в конце нет `.`, `!`, `?` или многоточия, перед синтезом добавляется точка. Отображаемый учебный текст не меняется. Речь сохраняет тембр постоянного образца, а не выбирает случайный голос для каждой записи.

Из корня проекта:

```sh
tts_work=$(mktemp -d)
export HF_HOME="$tts_work/cache/huggingface"
export XDG_CACHE_HOME="$tts_work/cache"
node scripts/build-content.mjs --audio-manifest "$tts_work/manifest.json"
CUDA_VISIBLE_DEVICES=0 .venv/bin/python scripts/tts/generate.py \
  --manifest "$tts_work/manifest.json" --out "$tts_work/wav"
.venv/bin/python scripts/tts/encode.py \
  --manifest "$tts_work/manifest.json" --input "$tts_work/wav" --out "$tts_work/m4a"
AUDIO_IMPORT_DIR="$tts_work/m4a" pnpm content
pnpm build
```

Манифест содержит уникальные `{file, text, voice}` и ничего не меняет в `public/` или `src/generated/`. Для параллельной генерации запустите несколько процессов с одинаковыми путями и разными `--shard N --shards K`, явно назначив доступные GPU через `CUDA_VISIBLE_DEVICES`. Один файл принадлежит только одному процессу. Готовые WAV используются повторно при продолжении прерванного запуска. Генерация объединяет фразы похожей длины в пакеты по восемь; параметры и seed каждого пакета сохраняются рядом с WAV. Число процессов и состав пакетов влияют на стохастический результат. Готовая партия использовала четыре shard-процесса; повторная генерация требует проверки произношения. Проверенные специальные варианты из `config.json → generation.curatedVariants` воспроизводятся после обычных пакетов. Их изменение автоматически меняет хэш аудио через конфигурацию.

`encode.py` удаляет только тишину по краям с запасом для согласных, выравнивает RMS с ограничением пика и создаёт M4A. `generation-report.json` содержит параметры длительности, усиления и SHA-256 каждого результата. Перед импортом проверьте количество файлов и прослушайте слова, числа и объявления. Импорт проверяет наличие всего недостающего набора до копирования и удаления старых аудио.

После проверки результата удалите своё временное окружение, WAV, кэши моделей и рабочий каталог. Для удалённой машины передавайте только манифест, скрипты, конфигурацию и образцы голосов; SSH-пароли в репозиторий не входят.
